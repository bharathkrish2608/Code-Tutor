CODE TUTOR: 6-WEEK DEVELOPMENT LOG
==================================
Project Context: Code Tutor (Django Backend, React+Vite Frontend)
Schedule: 6 Weeks, 5 Days/Week (Monday-Friday), 2.5 - 3.5 Hours/Day
Total Estimated Hours: ~90 hours

----------------------------------
WEEK 1: Foundation & Project Setup
----------------------------------
Day 1 (3 hours) - Environment Setup & Boilerplate
- Hour 1: Project ideation and mental mapping. Setting up the workspace folder `CODE TUTOR`.
- Hour 2: Backend initialization. Creating Python virtual environment, installing Django. Running `django-admin startproject config .` and `python manage.py startapp api`.
- Hour 3: Frontend initialization. Running `npm create vite@latest frontend --template react`. Cleaning up Vite boilerplate (removing unnecessary logos, cleaning App.css). Initializing Git repository.

Day 2 (3 hours) - Database Design & Django Configuration
- Hour 1: Configuring Django `settings.py`. Adding `api` to INSTALLED_APPS, setting up CORS headers for local development.
- Hour 2: Designing backend data structures. Writing `models.py` to store user code submissions, feedback results, and timestamps.
- Hour 3: Creating and running initial migrations (`python manage.py makemigrations`, `python manage.py migrate`). Writing `models_list.txt` to document schema design.

Day 3 (2.5 hours) - Django Admin & Basic Tests
- Hour 1: Registering models in `admin.py`. Creating a Django superuser to view data via `/admin`.
- Hour 2: Writing basic unit tests in `api/tests.py` and `test_models.py` to ensure models save and retrieve data correctly.
- Hour 0.5: Manually testing the SQLite database, validating the schema.

Day 4 (3 hours) - DRF Setup & Serializers
- Hour 1: Installing Django Rest Framework (DRF). Configuring settings to allow API access.
- Hour 2: Creating serializers in `api/serializers.py` (assumed) to convert Django models to JSON formats.
- Hour 3: Writing basic API views in `api/views.py` to accept POST requests with code snippets.

Day 5 (3.5 hours) - Week 1 Wrap-up & URL Routing
- Hour 1.5: Mapping endpoints in `api/urls.py` and connecting them to the main `config/urls.py`. 
- Hour 1: Testing the basic endpoints using Postman or cURL. Ensuring 200 OK responses.
- Hour 1: Committing Week 1 code, organizing directory structure, writing initial notes in `PROJECT_DETAILS.txt`.

----------------------------------
WEEK 2: The Core Logic - Analyzer Engine
----------------------------------
Day 6 (3 hours) - Designing the Code Analyzer
- Hour 1: Researching approaches to analyze code (AST parsing vs. LLM API integration).
- Hour 2: Creating `api/analyzer.py` skeleton. Defining the main functions (e.g., `analyze_code(code_string)`).
- Hour 3: Writing basic syntax checking logic in `analyzer.py` (e.g., using Python's built-in `ast` module or standard linting logic).

Day 7 (3.5 hours) - Implementing Feedback Generation
- Hour 2: Expanding `analyzer.py` to generate structured feedback (identifying variables, checking for basic complexity, or calling an external AI API if intended).
- Hour 1.5: Formatting the output into a standardized JSON response that the frontend can easily consume (error lines, suggestions, performance tips).

Day 8 (3 hours) - Connecting Analyzer to Views
- Hour 1.5: Modifying `views.py` to trigger `analyzer.py` when a POST request is received instead of just saving to the database.
- Hour 1.5: Handling errors (what if the user submits malformed code?). Adding try/except blocks and returning proper HTTP 400 responses.

Day 9 (2.5 hours) - Heavy API Testing
- Hour 1.5: Sending various code snippets (valid, invalid, malicious) via API testing tools to stress-test the analyzer.
- Hour 1: Reviewing logs and refining the traceback messages so they aren't overly verbose for the end-user.

Day 10 (3 hours) - Backend Refinement
- Hour 2: Optimizing database writes. Ensuring the analyzer response is saved to `db.sqlite3` asynchronously or efficiently before responding to the frontend.
- Hour 1: Documenting analyzer logic, cleaning up `__pycache__`, and wrapping up backend core for now.

----------------------------------
WEEK 3: Frontend Foundation
----------------------------------
Day 11 (3 hours) - React Architecture & Header
- Hour 1: Reviewing `package.json`, installing essential UI libraries (like Axios for requests, maybe a UI library like Tailwind or Material UI).
- Hour 1: Modifying `main.jsx` and `App.jsx` to establish global layout.
- Hour 1: Creating `src/components/Header.jsx` with branding and basic navigation structure.

Day 12 (3.5 hours) - The Code Editor Component
- Hour 1: Researching text editors for React (Monaco Editor, CodeMirror, or react-simple-code-editor). Installing chosen library.
- Hour 2.5: Building `CodeEditor.jsx`. Setting up state (`useState`) to capture user input. Handling syntax highlighting for Python/JS.

Day 13 (2.5 hours) - Code Editor Polish
- Hour 1: Adding line numbers, auto-indentation, and a "Submit" button to `CodeEditor.jsx`.
- Hour 1.5: Adding basic internal validation (preventing empty submissions) and lifting state up to `App.jsx` if necessary.

Day 14 (3 hours) - Feedback Display Component Structure
- Hour 1: Creating `FeedbackDisplay.jsx`. Designing how feedback will look (cards, lists, or a terminal-like window).
- Hour 2: Mocking JSON response data in the frontend to visualize the layout of `FeedbackDisplay.jsx` before actual backend integration.

Day 15 (3 hours) - Styling the Base Application
- Hour 2: Writing CSS in `index.css` and `App.css`. Establishing a clean, modern, dark-mode/developer-focused color palette.
- Hour 1: Applying CSS classes/modules to the `Header`, `CodeEditor`, and `FeedbackDisplay`.

----------------------------------
WEEK 4: The Great Integration
----------------------------------
Day 16 (3 hours) - API Services Setup
- Hour 1.5: Creating `src/services/api.js`. Writing reusable Axios fetch functions to communicate with the Django backend (`http://localhost:8000`).
- Hour 1.5: Dealing with CORS issues. Going back to Django `settings.py` to tweak `CORS_ALLOWED_ORIGINS` to allow Vite's `localhost:5173`.

Day 17 (3.5 hours) - Wiring the App Together
- Hour 2: Connecting the Submit button in `CodeEditor.jsx` to trigger the POST request via `services/api.js`.
- Hour 1.5: Managing loading states in React (`isLoading`, `error` states). Displaying a loading spinner while waiting for the analyzer to respond.

Day 18 (2.5 hours) - Rendering Real Feedback
- Hour 1.5: Passing the real API response data into `FeedbackDisplay.jsx`. Mapping over the feedback array and rendering React elements dynamically.
- Hour 1: Fixing data structure mismatches between what the Django API sends and what React expects.

Day 19 (3 hours) - Edge Cases and Error UI
- Hour 1.5: Building error state UI. If the backend fails (500 error) or the code is unanalyzable, showing a friendly error message instead of crashing.
- Hour 1.5: Testing massive code payloads to see how the UI handles overflow, adding scrollbars, fixing Flexbox/Grid alignment.

Day 20 (3 hours) - E2E Testing Round 1
- Hour 3: Putting on the "user hat". Typing code, pressing submit, reading feedback. Tweaking small annoyances (like clearing the editor, or adding a "Try Another" button).

----------------------------------
WEEK 5: Polish & Performance
----------------------------------
Day 21 (3.5 hours) - Advanced Styling & Responsiveness
- Hour 2: Making the app mobile-responsive using media queries in `index.css`/`App.css`. Stacking the Editor and Feedback side-by-side on desktop, but vertically on mobile.
- Hour 1.5: Improving button hover states, transitions, fonts, and scrollbar aesthetics.

Day 22 (2.5 hours) - Frontend Code Quality
- Hour 1.5: Reviewing `eslint.config.js`. Running linting checks, fixing unused variables, missing dependencies in `useEffect` arrays.
- Hour 1: Component refactoring. Splitting large components into smaller, more manageable sub-components if necessary.

Day 23 (3 hours) - Backend Refinement & Test Coverage
- Hour 2: Expanding tests in `test_models.py` and creating `test_results.txt` to log the output of automated backend tests. 
- Hour 1: Refining the Django Admin interface to easily monitor user submissions for debugging.

Day 24 (3 hours) - Encoding & Edge Case Bugs
- Hour 2: Handling UTF-8 encoding issues. Writing `test_results_utf8.txt` to ensure special characters (like emojis or foreign languages in comments) don't crash the Django parser.
- Hour 1: Updating `analyzer.py` to strip out dangerous system calls if executing code, or sanitizing inputs thoroughly.

Day 25 (2.5 hours) - Week 5 Review
- Hour 1.5: Synchronizing Git commits. Reviewing the entire codebase for consistency (naming conventions, docstrings).
- Hour 1: Doing a mini "feature-freeze." Deciding no more new features, only bug fixes from here on.

----------------------------------
WEEK 6: Finalization & Documentation
----------------------------------
Day 26 (3 hours) - Documentation & README
- Hour 2: Writing a comprehensive `README.md` in the frontend directory (how to install, start dev servers, environment variables).
- Hour 1: Updating `PROJECT_DETAILS.txt` with the finalized tech stack, core features, and architectural decisions.

Day 27 (3.5 hours) - Resume Framing & Portolfio Prep
- Hour 2.5: Writing `RESUME_CONTENT.txt`. Translating the work done over the last 5 weeks into actionable, impact-driven bullet points for a resume (e.g., "Architected a React/Django educational tool processing AST in real-time...").
- Hour 1: Capturing screenshots/GIFs of the working application for a portfolio.

Day 28 (2.5 hours) - Production Readiness
- Hour 1: Using `pip freeze > requirements.txt` to lock backend dependencies. 
- Hour 1.5: Checking `vite.config.js` and running `npm run build` to ensure the frontend compiles down to static assets without errors.

Day 29 (3 hours) - Final Bug Hunt
- Hour 2: Clicking everything. Submitting empty strings, 10,000 lines of code, breaking the network connection mid-request. 
- Hour 1: Fixing the final 2-3 minor UI glitches discovered during the bug hunt.

Day 30 (3 hours) - Project Wrap & Celebration
- Hour 1: Final Git commit. Pushing everything to a clean main branch on GitHub.
- Hour 1: Final review of the repository structure. Deleting any floating console.logs or print() statements.
- Hour 1: Project finished. Taking a moment to appreciate the completed CODE TUTOR software pipeline.
