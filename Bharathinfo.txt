1. HIGH-LEVEL VISION: THE WHY AND THE HOW
================================================================================

The AI Coding Tutor was born out of a simple observation: learning to code is
often a lonely and frustrating journey. Beginners frequently encounter syntax
errors or logical bugs that lead them to cryptic terminal messages. While a
pro experienced developer can decipher these, a beginner often feels discouraged.

--------------------------------------------------------------------------------
THE CORE PROBLEM:
--------------------------------------------------------------------------------
Traditional compilers and linters are built for professionals, not students. 
When a beginner sees "IndentationError: expected an indented block", they don't 
just need to know *where* it happened; they need to know *why* indentation 
matters in Python's syntax.

1. Cryptic Error Messages: Standard error outputs are too technical.
2. Lack of Context: Tutorials are static; they don't look at the user's specific code.
3. High Barrier to Entry: Setting up a local environment for feedback is hard.
4. Human Dependency: Tutors aren't available 24/7.

--------------------------------------------------------------------------------
THE SOLUTION: AI CODING TUTOR
--------------------------------------------------------------------------------
AI Coding Tutor acts as a "Pedagogical Bridge." It doesn't just fix the code;
it teaches the user why the mistake happened and how to avoid it in the future.
By leveraging Large Language Models (Gemini), it provides a personalized, 
encouraging, and structured learning environment that feels like a 1-on-1
mentorship session.

--------------------------------------------------------------------------------
CORE PHILOSOPHY:
--------------------------------------------------------------------------------
"Teaching over Fixing." Every response is structured to ensure conceptual 
understanding before providing the corrected code snippet. We prioritize:
- Clarity over Complexity.
- Encouragement over Criticism.
- Practicality over Theory.

2. TECHNICAL DEEP-DIVE: THE ENGINE UNDER THE HOOD
================================================================================

The project follows a modern decoupled architecture, separating the heavy AI
processing (Backend) from the interactive user experience (Frontend).

--------------------------------------------------------------------------------
BACKEND ARCHITECTURE (PYTHON / DJANGO)
--------------------------------------------------------------------------------
- Core Framework: Django 5.2.12. We chose Django for its "batteries-included" 
  philosophy, providing built-in security, admin interfaces, and ORM.
- API Framework: Django REST Framework (DRF). DRF allows us to build clean, 
  serialized endpoints that communicate seamlessly with React.
- AI Engine: Google Gemini AI (gemini-2.5-flash). We use the 2.5-flash model 
  because it offers the perfect balance:
    - Speed: Response times are sub-3 seconds.
    - Cost: Highly efficient token usage.
    - Reasoning: Exceptional at identifying logical flaws in code.
- Environment Management: python-dotenv. All secrets (API keys) are kept out 
  of the codebase for security.
- Security: django-cors-headers. This middleware is configured to allow 
  cross-origin requests from the Vite development server (Port 5173).

--------------------------------------------------------------------------------
FRONTEND ARCHITECTURE (JAVASCRIPT / REACT)
--------------------------------------------------------------------------------
- UI Library: React 19. Utilizing the latest concurrent rendering features 
  and improved hook patterns for state management.
- Build Tool: Vite. Replacing older tools like Webpack, Vite provides 
  instant server start and incredibly fast build times.
- Styling: Tailwind CSS 4.0 + Vanilla CSS. 
    - Tailwind handles layout, spacing, and responsive design.
    - Vanilla CSS handles the custom "Sketch" design tokens.
- Icons: Lucide React. Provides a set of clean, lightweight SVG icons.
- Markdown: React Markdown. AI responses are generated in Markdown; this 
  library ensures they are rendered as beautiful HTML.
- Highlighting: React Syntax Highlighter. Uses Prism.js to provide 
  IDE-quality coloring for code blocks in the feedback.

--------------------------------------------------------------------------------
CSS GLASSMORPHISM & SKETCH LOGIC
--------------------------------------------------------------------------------
The design system is a fusion of "Clean SaaS" and "Hand-drawn Notebook."

GLASSMORPHISM:
Applied primarily to the `Header` and `Sticky` elements.
Logic: `bg-white/90` combined with `backdrop-blur-md` and `border-b`. This 
creates a sense of depth and modern professionalism.

SKETCH AESTHETIC:
This is the unique "Bharath" touch.
- Box Sketch: Uses `border-radius: 8px 24px 12px 24px / 24px 8px 24px 16px` 
  to create an irregular, hand-drawn border effect.
- Rough Highlights: Uses absolute positioned pseudo-elements with a slight 
  rotation (-1deg to -2deg) and semi-transparent accent colors.
- Notebook Lines: A custom `repeating-linear-gradient` applied to the 
  feedback area to simulate lined paper.

3. DATABASE ARCHITECTURE: DATA & RELATIONSHIPS
================================================================================

The project uses SQLite (`db.sqlite3`) for development, which is a serverless, 
zero-configuration database engine.

--------------------------------------------------------------------------------
CONCEPTUAL DATA MODELS
--------------------------------------------------------------------------------

1. THE USER MODEL (Auth System)
   - Responsibility: Manages developer profiles, history, and login status.
   - Key Fields: Username, Email, Hashed Password.

2. THE SUBMISSION MODEL (Core Logic)
   - Responsibility: Stores every code snippet sent for analysis.
   - Fields:
     - `user`: ForeignKey (User) -> One user has many submissions.
     - `code_content`: TextField -> The raw code snippet.
     - `language`: CharField -> 'python', 'javascript', etc.
     - `timestamp`: DateTimeField -> When it was analyzed.

3. THE FEEDBACK MODEL (AI Results)
   - Responsibility: Stores the structured response from Gemini.
   - Fields:
     - `submission`: OneToOneField (Submission) -> One result per code snippet.
     - `raw_response`: TextField -> The full markdown generated by AI.
     - `status`: CharField -> 'success', 'error', 'pending'.

--------------------------------------------------------------------------------
RELATIONSHIP LOGIC (Users, Submissions, Results)
--------------------------------------------------------------------------------
Every piece of code "belongs" to a User.
Every Submission triggers exactly one Feedback generation.
This 1-to-N (User to Submission) and 1-to-1 (Submission to Feedback) 
relationship ensures we can track user progress over time, seeing how their 
coding mistakes decrease as they learn from the Tutor.

4. A-Z LOGIC FLOW: THE JOURNEY OF A CODE SNIPPET
================================================================================

Step-by-step walkthrough of what happens when a user clicks the "Analyze" button:

--------------------------------------------------------------------------------
PHASE 1: THE FRONTEND TRIGGER
--------------------------------------------------------------------------------
1. User input: The user types code into the `CodeEditor` component.
2. State update: React's `useState` hook updates the `code` variable in real-time.
3. Validation: When "Analyze" is clicked, `App.jsx` checks if the string is empty.
4. Loading state: `setIsAnalyzing(true)` is called, showing the "Waiting..." 
   UI and spinning icons.

--------------------------------------------------------------------------------
PHASE 2: THE API TRANSIT
--------------------------------------------------------------------------------
5. Service call: `services/api.js` is invoked. It uses `fetch()` to send a 
   POST request.
6. Headers: Content-Type is set to `application/json`.
7. Payload: The JSON body looks like: `{"code": "print('hello world')"}`.

--------------------------------------------------------------------------------
PHASE 3: THE BACKEND BRAIN
--------------------------------------------------------------------------------
8. URL Routing: Django's `config/urls.py` sends the request to `api/urls.py`, 
   which routes it to `AnalyzeCodeView`.
9. View Logic: The view extracts the code and instantiates the `CodeAnalyzer`.
10. AI Context Construction: The `CodeAnalyzer` class builds a massive 
    system prompt. It tells Gemini: "You are a tutor. Use these 6 sections. 
    Be kind."
11. Model Invocation: The prompt + user code are sent to the Gemini API.

--------------------------------------------------------------------------------
PHASE 4: THE RESPONSE & RENDERING
--------------------------------------------------------------------------------
12. AI Generation: Gemini returns a Markdown-formatted string.
13. JSON Response: The backend sends back `{"result": "...markdown..."}`.
14. React Update: `setResult(data.result)` updates the UI.
15. Markdown Rendering: `FeedbackDisplay.jsx` parses the markdown.
16. Code Highlighting: Any code blocks within the response are identified 
    and styled with Prism.js for maximum readability.

6. INSTALLATION & TROUBLESHOOTING: THE FOOLPROOF GUIDE
================================================================================

Follow these steps exactly to get the project running on any machine.

--------------------------------------------------------------------------------
STEP 1: SYSTEM REQUIREMENTS
--------------------------------------------------------------------------------
- Python 3.11+
- Node.js 20+
- A modern browser (Chrome, Firefox, Edge)
- A Google Gemini API Key

--------------------------------------------------------------------------------
STEP 2: BACKEND INSTALLATION
--------------------------------------------------------------------------------
1. Navigate to `/backend`.
2. Create environment: `python -m venv venv`
3. Activate environment:
   - Windows: `.\venv\Scripts\activate`
   - Mac: `source venv/bin/activate`
4. Install: `pip install -r requirements.txt`
5. Config: Create a `.env` file and add:
   `GEMINI_API_KEY=your_key_here`
6. Run: `python manage.py runserver`

--------------------------------------------------------------------------------
STEP 3: FRONTEND INSTALLATION
--------------------------------------------------------------------------------
1. Navigate to `/frontend`.
2. Install: `npm install`
3. Start: `npm run dev`
4. Access: Open http://localhost:5173

--------------------------------------------------------------------------------
TROUBLESHOOTING COMMON ISSUES
--------------------------------------------------------------------------------
- ISSUE: "ModuleNotFoundError" on Backend.
  - FIX: Ensure your virtual environment is active (you should see (venv) in 
    your terminal).
- ISSUE: "CORS Error" in Browser Console.
  - FIX: Check `backend/config/settings.py`. Ensure `CORS_ALLOW_ALL_ORIGINS` 
    is set to `True` for development.
- ISSUE: AI returns "Error: API Key not set".
  - FIX: Check the spelling of `GEMINI_API_KEY` in your `.env` file.
- ISSUE: Frontend says "Failed to fetch".
  - FIX: Ensure the Django server is running on Port 8000.

9. AI PROMPT ENGINEERING: THE SYSTEM PROMPT
================================================================================

The "System Prompt" in `analyzer.py` is over 40 lines of instructions. It is 
the most critical part of the project.

--------------------------------------------------------------------------------
WHY 6 SECTIONS?
--------------------------------------------------------------------------------
1. CODE ANALYSIS: Confirms we understood the user's intent.
2. MISTAKES FOUND: Transparently lists the errors.
3. EXPLANATION: The "Pedagogy" phase. We teach the concept.
4. CORRECTED CODE: The reward. A working solution.
5. KEY CONCEPT: A single word or phrase for the user to remember.
6. PRACTICE: Active learning. We don't just teach; we test.

This structure is strictly enforced. If the AI deviates, the frontend parsing 
might fail, which is why we use "Few-Shot Prompting" techniques within the 
code to guide the model.

12. DEEP DIVE: CORS & SECURITY CONFIGURATION
================================================================================

One of the most common pitfalls in Full-Stack development is CORS (Cross-Origin
Resource Sharing). Here is how we solved it in this project.

THE PROBLEM:
The Frontend runs on `localhost:5173`.
The Backend runs on `localhost:8000`.
By default, browsers block `5173` from talking to `8000` because they are 
different origins.

THE SOLUTION:
1. We installed `django-cors-headers` in the backend.
2. In `settings.py`, we added `'corsheaders'` to `INSTALLED_APPS`.
3. We added `'corsheaders.middleware.CorsMiddleware'` to the TOP of the 
   `MIDDLEWARE` list. This is crucial—it must run before other middleware.
4. We set `CORS_ALLOW_ALL_ORIGINS = True`. 
   *Developer Note*: In a production environment, you should replace this with:
   `CORS_ALLOWED_ORIGINS = ["https://yourdomain.com"]`.

13. THE AI SYSTEM PROMPT: A LINE-BY-LINE ANALYSIS
================================================================================

The system prompt is the invisible engine of the project. Let's look at why 
it works so well.

Line 21: "You are an expert AI Coding Tutor."
- Why: This sets the "Persona." It tells the model to use an educational tone.

Line 22: "Your goal is to provide highly structured, beginner-friendly feedback."
- Why: Forces the model to avoid jargon.

Line 24-39: The 6 Sections.
- Why: Consistency. This allows our Frontend to reliably parse the data. If the
  AI forgets a section, the UI might look empty.

Line 41-42: "Include hints but not full solutions." (For exercises)
- Why: Encourages active learning. If the AI gave the answer immediately, 
  the user wouldn't grow.

14. OPTIMIZATION & PERFORMANCE
================================================================================

We have taken several steps to ensure the app is fast and lightweight.

1. VITE BUNDLING:
   Vite uses ES Modules during development, which means it only compiles the 
   files you are actually looking at. This makes the dev experience 10x 
   faster than Create React App.

2. GEMINI 2.5 FLASH:
   We specifically chose the 'flash' model over 'pro' because 'pro' can take 
   10-15 seconds to respond. For a coding tutor, 3 seconds is the limit 
   before the user loses focus.

3. ASYNC FETCH:
   By using `async/await` in `api.js`, we ensure the UI remains responsive 
   even while the backend is thinking. The user can still interact with 
   the code editor while the analysis is pending.
